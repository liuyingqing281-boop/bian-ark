## 三、任务 C：合并前代码评审（持续）

对三分支 diff（feat/visual-polish、feat/payment、master 主线提交）按以下 checklist 评审：

### 安全（阻断级）
- [ ] 密钥/证书无硬编码、无进入日志（grep 扫描 AK/sk-/arn/wx 开头敏感串）
- [ ] 支付回调验签不可绕过；金额单位为分（整数）
- [ ] 越权：所有新 API 有登录/owner 校验（对照现有 permissions.ts 模式）
- [ ] SQL 无拼接（全部参数化）；路径处理有穿越防护
- [ ] 上传/生成类接口有 moderation 与配额

### 正确性（阻断级）
- [ ] 幂等：回调/重试路径重复执行无副作用
- [ ] 错误码 snake_case 且词典有 zh/en 映射（新 UI 文案必须进 dictionaries.ts）
- [ ] 迁移只用 `-- @add-column`/新增表，无破坏性变更

### 约定（建议级）
- [ ] trackEvent 埋点齐；smoke/E2E 有对应断言
- [ ] 文件边界遵守（对照各任务书「边界」节）
- [ ] 移动端硬指标（触控≥44px/字号≥12px/输入≥16px/无溢出）
- [ ] 视觉基调未偏离（深色石色+烛光暖金）

### 输出格式

```
## 评审：<分支/commit>
### 阻断（必须修）
- 文件:行号 — 问题 — 建议修法
### 建议（可选）
- ...
### 结论：可合并 / 修完阻断后合并 / 打回
```
