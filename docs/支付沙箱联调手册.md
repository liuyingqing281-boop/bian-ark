# 支付沙箱联调手册

## 本地配置

复制 `.env.example` 到本地环境，测试统一 mock 链路时设置：

```text
PAYMENT_PROVIDER=mock
DATABASE_PATH=data/bian.db
```

真实沙箱联调时删除 `PAYMENT_PROVIDER=mock`，填写微信支付 V3 或支付宝 RSA2 的商户参数。私钥、平台公钥只放 `.env.local` / `.env.production`，不要提交或打印日志。

## 下单

登录后调用：

```powershell
Invoke-RestMethod http://localhost:3003/api/payment -Method Post -ContentType 'application/json' -Body '{"provider":"mock","kind":"premium_monthly"}'
```

`dh_redo` 还需要传 `memorial_id`。金额始终由服务端按分计算，客户端金额不可信。

## Mock 回调

从 `orders` 查询 `provider_session_id` 后发送：

```powershell
$event = '{"id":"evt-local-1","type":"paid","sessionId":"ORDER_SESSION_ID","paymentId":"pay-local-1","amountCents":990,"currency":"CNY"}'
Invoke-RestMethod http://localhost:3003/api/payment/webhook/mock -Method Post -ContentType 'application/json' -Body $event
```

重复发送同一个 `id` 应返回 `duplicates: 1`，权益只发放一次。把 `type` 改成 `failed` 时订单失败且不发权益。

## 微信支付 V3

- Native 下单返回 `qr`，PC 端生成二维码。
- 移动 UA 使用 H5 下单接口并返回 `h5_url`；商户平台必须开通 H5 产品并配置域名 `bianmuyuan.cn`。
- 回调请求必须验证 `wechatpay-*` headers，并使用平台证书 RSA 验签、API V3 Key 解密 AES-256-GCM。
- 平台证书会从 `/v3/certificates` 下载并缓存到 `WECHAT_PAY_CERT_CACHE_PATH`。

## 支付宝

- 电脑端使用 `alipay.trade.page.pay`。
- 移动端使用 `alipay.trade.wap.pay`。
- 异步通知先 RSA2 验签，再按 `notify_id` 幂等处理。

## 验证命令

```powershell
npx tsc --noEmit
$env:PAYMENT_PROVIDER='mock'; npm run smoke:payment
```
