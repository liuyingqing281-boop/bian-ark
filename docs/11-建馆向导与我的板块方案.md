## R1 建馆入口与空态

### 前端

**空态引导页（无馆用户的首页，替代当前默认示例馆）**

```
┌──────────────────────────────┐
│                              │
│         [纸灯插画]            │
│   这里还空着，等一个故事      │
│                              │
│  【  为 TA 建一座纪念馆  】   │ ← 主 CTA 52px → 建馆向导
│                              │
│      先去公共墓园看看         │ ← 文字链 → 发现板块(R3)
└──────────────────────────────┘
```

- 判定逻辑：启动后 `GET /api/me/memorials`——有馆（owner/collaborator）→ 直达自己第一个馆的首页；无馆 → 空态引导页；访客（未登录）→ 保持公共示例馆演示（`?id=` 仍可指定任意公开馆）。
- 已有馆用户：屏02 首页 ⋯ 菜单新增「创建新纪念馆」项 → 同一建馆向导。
- 红线：空态不出现「暂无数据」式技术文案；按钮文案不出现「创建角色」，用「为 TA 建一座纪念馆」（§一-1 纪念馆是主体）。

### API 协议

| 接口 | 状态 | 说明 |
|---|---|---|
| `GET /api/me/memorials` | ✅ | 启动判空态的数据源；`items` 为空 → 空态引导页 |
| `POST /api/memorials` | 🟡 扩展 | 现有字段 `name/type/birthDate/deathDate/epitaph/biography`；**新增 `appellation`（称谓，如"爷爷"，≤10 字）**；响应保持 `201 { "id" }`；默认 `visibility=private`、`is_published=1`（V1 免审先上线，机审后置，见 04-PRD 建馆流程） |
| `POST /api/media` + `POST /api/upload` | ✅ | 头像上传：向导第 1 步选照片 → 上传得 `mediaId/url` → 建馆时带 `avatarUrl` |

### 数据仓库

- `memorials` 表 ✅ 已有 `appellation` 列（迁移 M1 已加），无需新表。
- 建馆即写 `memorial_audit_logs`（已有，action='create'）+ 埋点 `memorial_created`（已有）。

### 后端逻辑

1. `POST /api/memorials` 请求体增加 `appellation`（trim ≤10 字，默认空串）。
2. 空态判定全在后端：前端不自建规则，只读 `GET /api/me/memorials` 的 `items.length`。
3. 多馆切换：`?id=` 已支持；「我的纪念」点击条目即切换（原型已实现）。

## R2 记忆档案填写 + 建馆向导带资料

### 前端

**记忆档案空态（屏06 既有视图改一行）**

```
│   TA 的人生 · 记忆档案        │
│   还没有记录 TA 的故事        │
│  【  写第一条，一句话也好  】  │ ← 空态 CTA → F3 添加记忆抽屉（已有）
```

- 点击 = `openOverlay('memadd')`（现有链路，POST /api/memories source=manual，馆主/协作人权限）。

**建馆向导（3 步，单屏内分步，不改路由）**

```
第 1 步 TA 是谁          第 2 步 TA 的故事（选填）    第 3 步 确认
┌─────────────────┐   ┌──────────────────────┐   ┌─────────────────┐
│ 照片[+]          │   │ 👤 TA 是怎样的人 [+]  │   │ [照片]           │
│ 名字 ______     │   │ ❤️ 我和 TA     [+]    │   │ 爷爷 · 王守拙    │
│ 称谓 ______     │   │ 🎵 TA 喜欢什么 [+]    │   │ 1932 — 2023     │
│ 生卒 __ — __    │   │ 💬 TA 怎么说话 [+]    │   │ 已写 3 段故事    │
│ 类型 人/宠物/其他│   │ 📄 基础资料    [+]    │   │                  │
│ 【下一步】       │   │ 【上一步】【生成纪念馆】│   │ 【进入纪念馆】   │
└─────────────────┘   └──────────────────────┘   └─────────────────┘
```

- 第 2 步每个分区一个【+】→ 同 F3 抽屉（单条 ≤500 字），本地暂存数组；全可跳过。
- 第 2 步追加可选子项「TA 的声音」（FR-14，2026-08-23）：A 档预置音色试听/一句话描述生成；B 档上传生前语音复刻（强制授权勾选 + 人工审核）；规格见 `docs/14-语音能力方案.md` §2.3 与 web/01 §11.3；可整体跳过，未配置用系统默认音色。
- 第 3 步确认页只读展示，【生成纪念馆】= 一次建馆 + 批量写记忆（见下）。
- 文案红线：分区名逐字用 §2.5 既有命名，不出现「训练/资料库/AI」字样。

### API 协议（编排，不新开批量接口）

| 步骤 | 调用 | 说明 |
|---|---|---|
| 3-生成 | `POST /api/memorials` | 带第 1 步全部字段（含 `appellation/avatarUrl`）→ 得 `id` |
| 3-生成 | `POST /api/memories` × N | 第 2 步每条记忆一次调用，`{ memorialId: id, section, content, source: "manual" }`；馆主本人建馆即有权限（服务端已判 owner） |
| 3-失败补偿 | `DELETE /api/memorials/[id]` 🟡 | 建馆成功但记忆批量写部分失败时：已写保留（不阻断，toast「N 条已保存，M 条稍后可补」）；不删馆。DELETE 接口待开（见 R5-设置「删除纪念馆」复用） |

> 决策：不做 `POST /api/memorials/wizard` 聚合接口——逐条调用失败粒度可控，前端本地有暂存可重试，符合 §二「接口只增不减」原则。

### 数据仓库

- `memories` 表 ✅ 已有（B3），`source='manual'` 直写。
- 无新表、无新列。

### 后端逻辑

1. `POST /api/memorials` 写库后，`user_id` 即馆主 → 后续 `POST /api/memories` 走既有 owner 权限分支，无需改动。
2. 埋点新增：`wizard_step`（step=1/2/3）、`wizard_completed`（memorialId、memoryCount）——用于验证「建馆即带资料」是否降低空馆率（呼应 MRD 空馆焦虑结论）。

## R3 公共墓园 = 发现板块

### 前端

底部「发现」Tab 由 toast 占位改为 **garden 视图**（屏间新增，占屏号外序列，归入一级导航）：

```
┌──────────────────────────────┐
│ 公共墓园                      │
│ ┌──────────────────────────┐ │
│ │ 🔍 找一找那座纪念馆       │ │ ← 搜索（q 参数，≤40 字）
│ └──────────────────────────┘ │
│ ┌────────┐ ┌────────┐        │
│ │[照片]  │ │[照片]  │  …     │ ← 双列卡片流
│ │名字    │ │名字    │        │
│ │生卒年  │ │生卒年  │        │
│ └────────┘ └────────┘        │
└──────────────────────────────┘
```

- 卡片点击 → 以访客态进该馆首页（`ctx.setId(id)` + `go('home')`）。
- 空态：「墓园还很安静」；搜索无结果：「没有找到，换个名字试试」。
- 红线：不做排行/热度/打榜排序（§一-4），排序固定 `garden_slot`（运营人工位）。

### API 协议

| 接口 | 状态 | 说明 |
|---|---|---|
| `GET /api/garden?q=` | ✅ | 已返回公开墓园列表（`is_published=1 AND visibility='public' AND in_garden=1`），按 `garden_slot` 排序 |
| `PATCH /api/memorials/[id]/garden` | ✅ 已有路由 | 馆主把馆加入/移出公共墓园（`in_garden` 开关），屏02 ⋯ 菜单挂入口 |

> 适配层：garden 当前返回 snake_case，适配层转 `{ memorials: [{ id, name, avatarUrl, birthDate, deathDate, epitaph }] }`（§八既有口径）。

### 数据仓库

- `memorials.in_garden / garden_section / garden_slot` ✅ 已有列，无迁移。
- V1 不做分区（`garden_section` 保留给 V2「名人堂/普通园」分区）。

### 后端逻辑

无需改动；仅确认 `q` 参数防注入（已参数化 ✅）与结果上限（建议补 `LIMIT 100`，一行改动）。

### 新增接口协议

#### `GET /api/me/notifications` ❌→ 目标契约
```json
{ "items": [{ "id", "kind": "review|collab|system", "title": "你的纪念馆已通过审核",
             "body": "", "link": "/memorial/m_xxx", "read": false, "createdAt": "…" }],
  "unread": 2 }
```
- 倒序上限 50；`read` 批量置读 `POST /api/me/notifications/read { "ids": [...] }`（空数组=全读）。
- 产生源（V1 先接两类）：审核结论（memorials/items 审核状态变化时写入）、协作邀请被接受/退出。

#### `POST /api/feedback` ❌→ 目标契约
**请求**：`{ "content" (≤500, 必填), "contact?" (≤100) }` → `201 { "id" }`
- 过 `moderateText`；需登录（401）；同用户 60s 限频（429）。

#### `GET/PATCH /api/me/settings` ❌→ 目标契约
```json
// GET 200
{ "notifyReview": true, "notifyCollab": true, "privateDefault": false }
// PATCH 请求同名子集 → 200 { "ok": true }
```
- 存储：`users.settings`（新增 TEXT 列，JSON 串，默认 `{}`，读取时与默认值合并）。

#### `DELETE /api/memorials/[id]` ❌→ 目标契约
- 仅馆主；软删（`is_published=0` + `deleted_at` 新列）→ `204`；二次确认弹窗（赭红，§2.11）；写 `memorial_audit_logs` action='delete'。
- 关联数据（memories/messages/tributes）保留 30 天供找回，离线任务物理清理（迁移项，见下）。

### 数据仓库（本次新增/变更）

| 表/列 | 类型 | 说明 |
|---|---|---|
| `notifications` | 新表 | `id / user_id / kind / title / body / link / read(0/1) / created_at`；索引 `(user_id, read)` |
| `feedback` | 新表 | `id / user_id / content / contact / review_status / created_at` |
| `users.settings` | 新列 TEXT DEFAULT '{}' | JSON 串，键见 settings 契约 |
| `memorials.deleted_at` | 新列 TEXT DEFAULT '' | 软删标记；空串=未删除 |

迁移编号续 09 §B14（下一个序号），全部 `ALTER TABLE ADD COLUMN` / `CREATE TABLE IF NOT EXISTS`，无损。

### 后端逻辑要点

1. 通知写入点：审核通过/驳回（memorials、items 状态翻转处）、groups join/leave——统一 `lib/notify.ts` 加 `insertNotification(userId, kind, title, link)`。
2. 反馈与通知列表同样过打码/审核既有管线，不引入新旁路。
3. 软删纪念馆的可见性：所有 `memorials` 查询补 `AND deleted_at = ''`（一个公共查询助手 `getMemorialForAccess` 已集中，改一处即可）。

## 验收口径（对应 5 需求）

1. R1：新账号登录 → 首页无任何角色 → 点 CTA 建馆 → 首页出现新馆；老账号 ⋯ 菜单可见「创建新纪念馆」。
2. R2：空记忆档案显示【写第一条】且可保存；向导第 2 步填的内容在建馆完成后出现在对应分区。
3. R3：底部「发现」进公共墓园，可搜索、可进馆（访客态）。
4. R4：任一深层视图点底部三 Tab 均回对应一级视图，激活态正确。
5. R5：「我的」8 按键全部有真实接口响应（无 toast 占位）；通知有未读红点；反馈提交后 toast「已收到」。
