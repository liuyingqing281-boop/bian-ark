# 彼岸 · PC 端落地改造方案（原型 → Next.js 真实工程）

> 依据：`docs/web/01-PC前端设计文档.md`（布局/交互规范）、`docs/web/设计令牌.md`（视觉 SSOT）、`docs/web/02-PC后端设计文档.md`（后端增量）、`docs/web/04-PC断点走查清单.md`（已首轮验收通过的原型 `prototype/legacy/pc.html`）。
> 目标：把已验收的 PC 布局落到 `src/` 真实工程，接真实接口，**不重写移动端页面**——PC 适配以「同一页面组件 + PC 壳层 + 响应式分支」实现。
> 2026-08-23 基于 `src/` 实际结构编写。

## 一、现状盘点（已核实）

**已有路由**（`src/app/[lang]/`）：`hall/[id]`（纪念馆首页，含供奉/feed/对话）、`miss`、`memory/[id]`（记忆档案）、`gift/[id]`（AI 纪念物三步流）、`family/[id]`（亲友）、`me`、`garden`（发现）、`login`、`membership` 等。

**已有组件**（`src/components/hall/`）：`HallChat`（对话）、`MissComposer`（留言）、`HallOffer`（供奉）、`FeedList`（纪念流）、`MemoryDrawer`、`FamilyPanel`、`GiftFlow`，另有 `MemorialHero`、`Flame` 等。

**结论**：页面与组件已齐备且功能全部冒烟通过（见 `docs/07-联调记录.md`）；PC 落地 = **加壳层与响应式布局，不动业务逻辑**。

## 二、总体策略：一套组件，两端布局

```
移动端（<768px）          PC 端（≥768px）
底部 Tab 导航        →    左导航 224px（≤1024px 收 64px 图标栏）
页面级路由切换        →    同路由 + 宽屏布局分支
对话独立页/抽屉      →    全局覆盖式对话侧板（可收起，不占路由）
单列信息流           →    1120px 限宽容器 + 12 列（8+4）网格
```

- **不做独立 PC 页面**（避免与移动端逻辑双份维护）；用 `useMediaQuery` / CSS 媒体查询在同一组件内分支。
- 视觉零新增：全部引用 `设计令牌.md`；`globals.css` 已含熔火主题变量，PC 壳层只加布局 class。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 同组件两端分支导致复杂度上升 | PC 分支只做布局类与条件 class，业务逻辑/数据流不分叉；超过 50 行差异的区块抽独立 PC 子组件 |
| `HallChat` 复用冲突（页面态 vs 侧板态） | 侧板复用其数据 hook 与消息渲染，壳（顶栏/输入区定位）自控；必要时抽 `ChatMessages` 共用子组件 |
| 后端分页接口延期 | M1–M3 不阻塞；M4 前必须就绪，否则「查看全部」降级为跳移动端流式页 |
| SSR/SEO（纪念馆公开页） | M4 后评估，V1 不做 |
