## 二、接口实际返回样例

### GET /api/hall/feed?memorial_id=4fc5e476-…

200，按 `createdAt` 倒序，混合两种 kind（截取首尾各一条）：

```json
{
  "items": [
    { "kind": "tribute", "icon": "🏮", "label": "献上长明灯", "senderMasked": "匿**", "message": "", "isBurning": false, "createdAt": "2026-08-22 16:42:26" },
    { "kind": "message", "icon": "💬", "label": "留下思念", "senderMasked": "访客", "message": "总回归留言：一直想念您", "isBurning": false, "createdAt": "2026-08-22 16:42:22" }
  ]
}
```

- `kind`：`tribute`（icon/label 来自 items 表，label 为「献上{item.name}」）| `message`（public→💬 留下思念；eulogy→🕯️ 写下悼文）
- `senderMasked`：tribute 用 `sender_name`、message 用 `users.name`，均首字符+`**`；无名字回落「访客」。实测样例：`匿**`、`刘**`、`学**`、`测**`
- `private`（悄悄话）不进流；未过审核（review_status≠approved）不进流；不存在/未发布的纪念馆返回 `{ "items": [] }`
- 单源各取最近 100 条，合并排序后截断 50 条

## 三、合并后发现的待办（不属 D 范围，仅记录）

1. **`GET /api/messages` 对匿名请求返回了 private 消息**：上例中 `回归负例悄悄话`（user_id=''）出现在匿名 GET 结果里。原因推测：seed 数据 user_id 为空串，与匿名请求的"本人"判定撞车。feed 侧不受影响（SQL 直读时已过滤 private）。建议 A 方确认可见性过滤对 `user_id=''` 的处理。
2. `feed` 的 `createdAt` 为 SQLite `datetime('now')` 格式（`YYYY-MM-DD HH:MM:SS`，UTC），前端展示需注意时区换算。
3. 回归脚本每次运行会追加 seed 数据（留言/悼文/订单），属一次性冒烟数据，不影响断言幂等。
