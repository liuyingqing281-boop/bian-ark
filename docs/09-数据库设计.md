# 彼岸 · 数据库设计

> 依据：《前端具体设计流程.md》交互拆解 + `migrations/001–014` 现有 schema 实测核对。
> 引擎：SQLite（`data/bian.db`，better-sqlite3）；迁移走 `tools/db-migrate.mjs`（版本化、可回滚、`-- @add-column` 指令支持）。
> 约定：主键 `TEXT`（uuid）；时间 `TEXT` UTC ISO；金额 `INTEGER` 分（`*_cents`）；布尔 `INTEGER 0/1`；审核统一 `review_status`（`approved/pending/rejected`）+ `review_reason`；文案红线 = 无虚拟币/积分/排行榜任何字段。

### 2.8 `orders` / `payment_events` 一口价订单 ✅ 已有（005）

`orders`：`id PK / user_id / kind（item/gift/membership…）/ provider='stripe' / provider_session_id UNIQUE / status(pending|paid|refunded|failed) / amount_cents / currency='cny' / created_at / updated_at`。

`payment_events`：`provider_event_id PK`（webhook 幂等）`/ event_type / payload / processed_at`。

设计要点：只有单次支付订单，**无订阅、无自动续费、无钱包余额表**——红线在 schema 层即不可表达。

### 2.9 `ai_generation_jobs` 生成任务 ✅ 已有（005）

`id PK / user_id / idempotency_key / provider / provider_task_id / status(pending|running|succeeded|failed) / prompt / candidates(JSON) / error / duration_ms / created_at`，`UNIQUE(user_id, idempotency_key)`。
失败退费 = job `failed` + order `refunded` 联动（应用层）。

### 2.10 `prompt_quota` 帮我写限量 ✅ 已有（011）

按 (user_id, day) 计数，超限 429。09 屏「每日限量 · 明天再来」。

### 2.11 协作与权限族 ✅ 已有（002）

- `groups`：`id PK / name / owner_user_id / invite_code UNIQUE / created_at`
- `group_members`：`(group_id, user_id) PK / role(owner|collaborator|member) / joined_at`
- `memorial_groups`：`(memorial_id, group_id) PK`（馆 ↔ 组绑定）

权限判定集中在 `lib/permissions.ts`：`canViewMemorial` / `canManageMemorial`（馆主或协作人）。

### 2.12 账号族 ✅ 已有（001/002/004）

- `users`：`id PK / email UNIQUE / name / membership_tier='free' / membership_expires_at / stripe_customer_id / created_at`
- `sessions`：`token PK / user_id / expires_at / created_at`（Cookie 会话）
- `login_codes`：`channel/target/code/expires_at/attempts/used`（验证码，带尝试次数）

## 四、一致性与红线核对

1. **打码**：所有对外列表的昵称打码在查询/输出层做（`maskName`），库内原文——满足「不展示可识别个人身份的信息」。
2. **悄悄话存在性保护**：越权读 private 返回过滤后列表而非 403，不泄露「有没有悄悄话」。
3. **游客态**：chat 不落库、messages 不可写、tributes 可匿名供奉（sender_name 默认 Anonymous）——与原型访客语义一致。
4. **商业化红线**：schema 全量 grep 无 `coin/point/balance/pack/rank` 字段；付费只有「一口价订单 → 支付回调 → 供奉/生成」一条链。
5. **审核**：UGC 四表（memories/messages/tributes/media/items 生成物）统一 `review_status` 约定，申诉走 `moderation_appeals`。
