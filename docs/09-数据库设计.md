# 彼岸 · 数据库设计（前后端分离版）

> 依据：《前端具体设计流程.md》交互拆解 + `migrations/001–014` 现有 schema 实测核对。
> 本文分上下两篇：**上篇 · 前端数据设计**（前端只面对「数据视图契约」，不感知物理表、不感知 SQL）；**下篇 · 后端数据设计**（物理表、索引、迁移、权限落库规则）。
> 分界原则：前端消费的是「接口返回的视图模型」，后端负责「视图模型 ↔ 物理表」的装配与拆解；前端永不直接引用表名/字段物理名以外的知识。

---

# 上篇 · 前端数据设计（视图契约层）

> 前端所有页面数据来自 6 个视图模型（ViewModel），与《API 接口说明书》响应体一一对应。前端开发只需本篇。

## F1. 纪念馆视图 `MemorialView` — 01 屏首页 / 03 屏说明页 / 04 屏顶栏

```ts
interface MemorialView {
  id: string;
  name: string;             // TA 的名字
  appellation: string;      // 称谓「爷爷」，空则前端回落「TA」【待确认⑧】
  birthDate: string;        // 1940
  deathDate: string;        // 2023
  epitaph: string;          // 寄语
  avatarUrl: string;
  viewerRole: 'owner' | 'collaborator' | 'member' | 'guest'; // 决定 ⋯ 菜单与【+】可见性
  candleLit: boolean;       // 你点的灯还亮着【待确认①】
  candleLitHours: number;
}
```

**页面消费规则**：
- 01 屏 ⋯ 菜单：`owner/collaborator` 显示 分享/编辑/协作；其余显示 举报。
- 01 屏时间线【+】、05 屏记忆编辑/删除：仅 `owner/collaborator`。
- 04 屏标题：`和 ${appellation || 'TA'} 说说话`。

## F2. 时间线视图 `TimelineItem[]` — 01 屏「TA 的人生」

```ts
interface TimelineItem {
  id: string;
  year: string;
  title: string;
  description: string;
  imageUrl: string | null;  // 图文卡片「1978 · 青岛看海」【待确认⑨】
}
```
按 year 升序渲染；空数组 → 空状态「还没有记录 TA 的故事」+ 引导按钮（仅管理者可点）。

## F3. 纪念流视图 `FeedItem[]` — 01 屏「最近的纪念」

```ts
interface FeedItem {
  kind: 'tribute' | 'message';
  icon: string;            // 🌸💬🕯️
  label: string;           // 「献上鲜花 / 留下思念 / 写下悼文」
  senderMasked: string;    // 已打码「李**」，前端直接使用，禁止自行拼接原文
  message: string;
  isMine: boolean;         // 悄悄话条目「我」的展示依据
  isBurning: boolean;
  createdAt: string;       // UTC，前端负责时区换算 + 相对时间「2 小时前」
}
```
超过 5 条折叠为「查看全部纪念」；空数组 → 「成为第一个纪念 TA 的人」。

## F4. 记忆档案视图 `MemoryArchiveView` — 05/06 屏

```ts
type MemorySection = 'personality' | 'relation' | 'likes' | 'speech' | 'profile';
interface MemoryArchiveView {
  total: number;                                   // 「已建立 32 条记忆」
  sections: Record<MemorySection, MemoryEntry[]>;  // 5 分区固定齐全，空分区给 []
}
interface MemoryEntry { id: string; section: MemorySection; content: string;
  source: 'manual' | 'chat'; createdAt: string; }
```
- 分区元数据（图标/标题/空状态文案）为前端常量，不下发：
  `personality` 👤 TA 是怎样的人｜`relation` ❤️ 我和 TA（关系记忆，视觉强调）｜`likes` 🎵 TA 喜欢什么｜`speech` 💬 TA 怎么说话｜`profile` 📄 基础资料。
- 写操作（增/改/删）仅在 `viewerRole ∈ {owner, collaborator}` 时渲染入口；「补充记忆」入口例外，见 F5。

## F5. 对话视图 `ChatReply` — 04 屏

```ts
interface ChatReply {
  text: string;
  evidence: { memoryId: string; quote: string; createdAt: string } | null; // null = 不渲染依据链接
  inferred: boolean;        // true → 渲染「基于 TA 的资料推测」角标（不可关闭）
  askMemory: boolean;       // true → 渲染「添加一段关于 TA 的记忆」按钮
  followupQuestion: string | null;  // 引导问题「爷爷什么时候开始喜欢钓鱼？」
}
```
状态机（前端本地）：`sending → streaming(正在想你问的话…) → done | error(重试) | blocked(轻轻带过)`。历史记录 `ChatHistoryItem[]` 结构同 role+content+evidenceMemoryId【待确认④】。

## F6. 祭奠与商业化视图 — 07/08/09/10 屏

```ts
interface ItemView {        // 宫格
  id: string; name: string; imageUrl: string;
  priceCents: number;       // 0 → 显示「免费」角标；>0 → 直接显示 ¥X（点击前可见）
  isPremium: boolean;
}
interface OrderView {       // 10 屏订单流水
  id: string; itemName: string; amountCents: number; currency: 'cny';
  status: 'pending' | 'paid' | 'refunded' | 'failed'; createdAt: string;
}
interface GiftJobView {     // 09 屏三步流
  jobId: string; status: 'pending' | 'running' | 'succeeded' | 'failed';
  imageUrl: string | null; promptUsed: string;   // 流程回顾区
}
```

**前端红线（与后端 schema 互锁）**：视图模型中没有也不允许出现余额/币值/礼包/榜单字段；价格唯一来源 `priceCents`。

## 前端通用规则

1. 所有列表必须处理 **空 / 加载 / 错误** 三态（设计流程 §一-6）。
2. 打码只在后端做；前端拿到的 `senderMasked`/`nameMasked` 直接渲染。
3. 时间一律 UTC 进、本地时区 + 相对时间出。
4. 权限相关 UI 一律以视图中的 `viewerRole` 为准，不做本地推断。

# 下篇 · 后端数据设计（物理存储层）

> 引擎：SQLite（`data/bian.db`，better-sqlite3）；迁移走 `tools/db-migrate.mjs`（版本化、可回滚、`-- @add-column` 指令支持）。
> 约定：主键 `TEXT`（uuid）；时间 `TEXT` UTC ISO；金额 `INTEGER` 分；布尔 `INTEGER 0/1`；审核统一 `review_status(approved/pending/rejected)` + `review_reason`；红线 = 无虚拟币/积分/排行榜任何字段。

## B0. ER 总览

```
users ──< sessions / login_codes / orders / ai_generation_jobs / data_requests / moderation_appeals
orders ──< payment_events
ai_generation_jobs ──> items（claim 后）
memorials ──< life_events / memories / messages / tributes / chat_messages / media / customizations
tributes >── items
memorials >──< groups（memorial_groups）──< group_members >── users
memorials ──< digital_humans（暂缓）
prompt_quota（每日限量）· events（埋点）
```

**视图模型 → 物理表装配关系**（后端职责，前端无感）：

| 视图模型 | 装配来源 |
|---|---|
| F1 MemorialView | `memorials` + `tributes`(is_burning, 24h 窗口推断 candleLit) |
| F2 TimelineItem | `life_events`（+ `media`，待确认⑨） |
| F3 FeedItem | `tributes ⋈ items` ∪ `messages ⋈ users`，排序截断 50，输出层 `maskName` |
| F4 MemoryArchiveView | `memories` 按 section 分组 + count |
| F5 ChatReply | `lib/chat-prompt` 装配 `memories`+`life_events`+`memorials` → LLM JSON → 依据回查 `memories`；落库 `chat_messages` |
| F6 ItemView/OrderView/GiftJobView | `items` / `orders` / `ai_generation_jobs` |

## B1. `memorials` 纪念馆 ✅ 已有（001）

| type | TEXT DEFAULT 'person' | 预留 |

| biography | TEXT | 生平长文（chat prompt 回落语料） |

> 待确认⑧：加列 `appellation TEXT DEFAULT ''`（称谓「爷爷」），当前唯一结构性缺口。

## B2. `life_events` 生平时间线 ✅ 已有（003）

`id PK / memorial_id / user_id / year NOT NULL / title NOT NULL / description / sort_order / created_at`。
> 待确认⑨：图文卡片图片来源——建议加可空列 `media_id` 关联 `media` 表。

## B3. `memories` 记忆档案 ✅ 已有（013）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | |
| memorial_id | TEXT NOT NULL | |
| user_id | TEXT | 录入人（chat 闭环时为普通用户） |
| section | TEXT NOT NULL | 枚举 `personality/relation/likes/speech/profile`（应用层 `isMemorySection` 校验） |
| content | TEXT NOT NULL | ≤500 字 |
| source | TEXT DEFAULT '' | `manual` / `chat` |
| review_status / review_reason | TEXT | |
| created_at / updated_at | TEXT | |

索引：`idx_memories_memorial_section(memorial_id, section, created_at)`。
chat 装配上限 100 条（`created_at ASC`），超量截断策略待确认⑩。

## B4. `messages` 留言/悄悄话/悼文 ✅ 已有（014）

`id PK / memorial_id NOT NULL / user_id / msg_type NOT NULL(public|private|eulogy) / content NOT NULL(≤500) / review_status / review_reason / created_at`。
索引：`idx_messages_memorial_type(memorial_id, msg_type, created_at)`。
可见性服务端强制：`private` 仅作者可读（越权返回过滤后列表，不泄露存在性）；`eulogy` 置顶为排序规则【待确认②是否加 `is_pinned`】。

## B5. `chat_messages` 对话历史 ✅ 已有（012）

`id PK / memorial_id NOT NULL / user_id（NULL=游客不落库）/ role CHECK IN ('user','ta') / content NOT NULL / evidence_memory_id NULL→memories.id / created_at`。
索引：`idx_chat_messages_memorial_created(memorial_id, created_at)`。
> 开 history 接口时补索引 `(memorial_id, user_id, created_at)`（待确认④关联）。

## B6. `items` 祭品目录 ✅ 已有（001 + 005 扩展）

`id PK / name / category / icon / image_url / price_cents（0=免费三项；>0=一口价）/ is_premium / sort_order / memorial_id / source / review_status`（后三项服务 AI 生成物认领，`pending` 审核前仅本人可见）。
红线：全表无 `coin/points/gift_pack` 变体；价格唯一口径 `price_cents`。

## B7. `tributes` 供奉记录 ✅ 已有（001 + 008）

`id PK / memorial_id FK / item_id→items / message / sender_name DEFAULT 'Anonymous' / is_burning（点灯态，24h 窗口查询层判）/ order_id（付费供奉关联，免费为空）/ review_status / review_reason / created_at`。

## B8. `orders` / `payment_events` ✅ 已有（005）

`orders`：`id PK / user_id / kind / provider='stripe' / provider_session_id UNIQUE / status(pending|paid|refunded|failed) / amount_cents / currency='cny' / created_at / updated_at`。
`payment_events`：`provider_event_id PK`（webhook 幂等）`/ event_type / payload / processed_at`。
要点：只有单次支付订单，**无订阅、无自动续费、无钱包余额表**——红线在 schema 层不可表达。

## B9. `ai_generation_jobs` ✅ 已有（005）

`id PK / user_id / idempotency_key / provider / provider_task_id / status(pending|running|succeeded|failed) / prompt / candidates(JSON) / error / duration_ms / created_at`，`UNIQUE(user_id, idempotency_key)`。失败退费 = job failed + order refunded 应用层联动。

## B10. `prompt_quota` ✅ 已有（011）

按 (user_id, day) 计数，超限 429。

## B11. 协作与权限族 ✅ 已有（002）

- `groups`：`id PK / name / owner_user_id / invite_code UNIQUE / created_at`
- `group_members`：`(group_id, user_id) PK / role(owner|collaborator|member) / joined_at`
- `memorial_groups`：`(memorial_id, group_id) PK`

权限判定集中在 `lib/permissions.ts`（`canViewMemorial` / `canManageMemorial`），装配 F1 的 `viewerRole`。

## B12. 账号族 ✅ 已有（001/002/004）

`users(id PK / email UNIQUE / name / membership_tier='free' / membership_expires_at / stripe_customer_id / created_at)`、`sessions(token PK / user_id / expires_at)`、`login_codes(channel/target/code/expires_at/attempts/used)`。

## B13. 其余已有表（不动）

`media`（照片+审核）、`customizations`、`events`（埋点）、`digital_humans`+`dh_redo_credits`（暂缓）、`moderation_appeals`、`data_requests`（注销/导出）、`schema_migrations`。

## B15. 一致性与红线核对

1. 打码只在输出层（`maskName`），库内原文。
2. 悄悄话越权返回过滤列表而非 403，不泄露存在性。
3. 游客态：chat 不落库、messages 不可写、tributes 可匿名供奉。
4. 商业化红线：全库无 `coin/point/balance/pack/rank` 字段；付费仅「一口价订单→回调→供奉/生成」单链。
5. UGC 四表（memories/messages/tributes/media + items 生成物）统一 `review_status` 约定，申诉走 `moderation_appeals`。
