## 【阻断级】必须修改

### 阻断-001：moderationEnabled() 默认不启用

**位置**：`src/lib/moderation.ts:76`
```typescript
if (!moderationEnabled()) return { pass: true, status: "pending", reason: "moderation_not_configured" };
```
**问题**：当环境变量未配置时，`moderateText()` 返回 `pass: true`（通过），仅标记 `pending`。

**风险**：备案材料声称「所有生成请求均经内容安全审核」，但实际未配置阿里云密钥时审核被跳过。此为**实际未兑现的安全措施**，核查打回风险高。

**建议**：
1. **方案A（推荐）**：将默认行为改为 `fail-closed`：
   ```typescript
   if (!moderationEnabled()) return { pass: false, status: "pending", reason: "moderation_not_configured" };
   ```
2. **方案B**：在备案材料中明确说明「未配置时进入人工审核队列兜底」。

**结论**：方案A更合规，需 GLM5.3 评估用户体验影响。

### 阻断-002：delete_memorial 未级联清理 uploads 文件

**位置**：`src/app/api/admin/route.ts:120-123`
```typescript
if (action === "delete_memorial") {
  db.prepare("DELETE FROM tributes WHERE memorial_id = ?").run(payload.id);
  db.prepare("DELETE FROM memorials WHERE id = ?").run(payload.id);
}
```

**问题**：
- `memorials/[id]/route.ts` 完整级联清理（8张表）
- 但 `admin/route.ts` 仅删除 tributes/memorials，遗漏：
  - media 表文件记录
  - digital_humans 视频文件
  - 上传目录物理文件

**风险**：备案材料声称「纪念馆删除时级联清理全部素材」，admin 删除不走级联。

**建议**：统一删除逻辑，复用 memorials/[id]/route.ts 的 DELETE 逻辑。
