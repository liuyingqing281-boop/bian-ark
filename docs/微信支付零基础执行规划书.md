# 微信支付 V3 零基础执行规划书

> 适用项目：彼岸 ｜ 生产域名：`https://bianmuyuan.cn` ｜ 支付分支：`feat/payment`
>
> 目标：让没有支付开发经验的人，也能从商户准备开始，完成代码合并、服务器配置、Native/H5 下单、回调验签、权益到账和回滚验收。

## 0. 先理解最终结果

完成后，用户会经历下面的流程：

1. 用户登录彼岸。
2. 用户在会员页选择微信支付，或在数字人页面购买重做额度。
3. 电脑端得到扫码二维码；手机端跳转微信 H5 收银台。
4. 用户付款。
5. 微信服务器向彼岸发送支付回调。
6. 彼岸验证微信签名、解密回调并核对金额。
7. 订单变为 `paid`，会员或数字人重做额度到账。
8. 微信重复发送回调时，不会重复发权益。

不要在浏览器地址栏打开 webhook 地址。它只接受微信服务器发送的 `POST` 请求，浏览器 `GET` 得到 404 是正常现象。

## 1. 人员分工

| 角色 | 需要做什么 |
|---|---|
| 刘贻清 | 申请微信支付、取得商户资料、填写生产密钥、完成真实付款 |
| GPT 支付分支 | 支付代码、测试、文档，推送 `feat/payment` |
| GLM 集成方 | 审查并合并分支、部署生产、执行生产检查 |
| Opus 评审方 | 检查密钥、验签、金额、幂等和权限是否存在阻断问题 |

任何人都不要把私钥、API V3 Key、完整回调报文发到群聊、Issue、截图或 Git。

## 2. 第一阶段：确认商户资格

### 2.1 打开商户平台

1. 打开 `https://pay.weixin.qq.com/`。
2. 使用管理员微信扫码登录。
3. 确认登录后能看到商户平台，而不是“申请接入”页面。
4. 在页面中记录商户号，通常简称 `mchid`。

成功标志：你已经拿到一个商户号，例如 `190000xxxx`。

如果没有商户号：先完成主体、法人、结算账户和经营资料审核。审核通过前不能继续真实支付联调，但可以继续本地 Mock 测试。

### 2.2 确认支付产品权限

在商户平台的产品或产品中心页面确认：

- Native 支付已开通，用于电脑网页扫码。
- H5 支付已开通，用于手机浏览器跳转。
- 商户号已与使用的 AppID 建立绑定关系。

成功标志：Native 和 H5 都显示已开通，AppID 绑定已生效。

如果 H5 未开通：PC 扫码仍可继续验收，但手机 H5 下单会被微信拒绝。不要把这种情况误判为代码错误。

### 2.3 准备 AppID

项目优先读取：

```text
WECHAT_PAY_APP_ID
```

未填写时会兼容读取登录模块的：

```text
WECHAT_APP_ID
```

建议支付单独填写 `WECHAT_PAY_APP_ID`，避免登录和支付应用混淆。

成功标志：AppID 与商户号已经绑定，且属于同一主体或符合微信授权关系。

## 3. 第二阶段：生成和保存支付密钥

### 3.1 设置 API V3 Key

1. 在微信支付商户平台进入 API 安全或账户中心的 API 安全页面。
2. 找到 API V3 Key 设置入口。
3. 生成一个恰好 32 字节的高强度随机值。
4. 保存到密码管理器，变量名记为：

```text
WECHAT_PAY_API_V3_KEY
```

成功标志：值的 UTF-8 字节长度为 32。

禁止事项：

- 不要使用公司名、手机号、域名或连续数字。
- 不要提交到 `.env.example`。
- 不要把值写进代码或运维日志。

### 3.2 申请商户 API 证书

1. 在 API 安全页面申请商户 API 证书。
2. 按微信提供的证书工具流程生成证书。
3. 安全保存以下内容：
   - 商户私钥文件，通常是 `apiclient_key.pem`。
   - 商户证书文件，通常是 `apiclient_cert.pem`。
   - 商户证书序列号。
4. 把商户私钥内容对应到：

```text
WECHAT_PAY_PRIVATE_KEY
```

5. 把证书序列号对应到：

```text
WECHAT_PAY_SERIAL_NO
```

成功标志：私钥以类似下面的头尾包裹：

```text
-----BEGIN PRIVATE KEY-----
...
-----END PRIVATE KEY-----
```

不要把证书序列号误当作商户号，也不要把平台证书误当作商户私钥。

## 5. 第四阶段：代码评审与合并

### 5.1 支付分支提交

```powershell

git add <本次需要提交的支付文件>

```

成功标志：输出包含：

```text

```

### 5.2 交给 Opus 评审

把 `master...feat/payment` 的 diff 交给 Opus，必须检查：

- 没有私钥、API V3 Key、证书内容或真实 token。
- webhook 缺少签名时必定失败。
- 微信回调按 `wechatpay-serial` 选择平台证书。
- 金额必须存在、是整数且与订单金额相同。
- 币种必须是 CNY。
- 重复 event id 不重复发会员或重做额度。
- `dh_redo` 只能由纪念馆所有者购买。
- SQL 全部参数化。

只有结论为“可合并”或“修完阻断后合并”且阻断已清零，才能进入下一步。

### 5.3 集成方合并


### 6.3 编辑生产环境变量

```bash
nano /var/www/bian/.env.production
```

填写：

```text
WECHAT_PAY_APP_ID=这里填AppID
WECHAT_PAY_MCH_ID=这里填商户号
WECHAT_PAY_API_V3_KEY=这里填32字节V3Key
WECHAT_PAY_SERIAL_NO=这里填商户证书序列号
```

### 6.4 限制环境文件权限

```bash

ls -l /var/www/bian/.env.production
```

### 6.5 检查变量是否存在但不打印密钥

```bash
for key in WECHAT_PAY_APP_ID WECHAT_PAY_MCH_ID WECHAT_PAY_API_V3_KEY WECHAT_PAY_SERIAL_NO WECHAT_PAY_PRIVATE_KEY WECHAT_PAY_NOTIFY_URL; do
```

## 11. 第十阶段：回调与证书验收

### 11.1 检查证书缓存

第一次真实回调后：

```bash
ls -l /var/www/bian/data/payment/wechat-platform-certs.json
```

预期文件存在。不要把文件内容打印到日志或发到聊天。

### 11.2 检查回调幂等

查询事件：

```bash
sqlite3 /var/www/bian/data/bian.db "SELECT provider_event_id,event_type,processed_at FROM payment_events ORDER BY processed_at DESC LIMIT 10;"
```

预期微信事件 id 只出现一次，前缀为 `wechat:`。

微信重复通知时，接口仍返回成功，但会员期限或数字人额度不能再次增加。

### 11.3 检查错误签名

以下命令仅验证“伪造请求不能通过”，不会产生真实支付：

```bash
curl -i -X POST 'https://bianmuyuan.cn/api/payment/webhook/wechat' \
  -H 'Content-Type: application/json' \
  -H 'Wechatpay-Timestamp: 1' \
  -H 'Wechatpay-Nonce: invalid' \
  -H 'Wechatpay-Serial: invalid' \
  -H 'Wechatpay-Signature: invalid' \
  --data '{}'
```

预期 HTTP 400。若返回 HTTP 200，立即停止上线，这是阻断级安全问题。

### 11.4 检查自动证书刷新

1. 先备份缓存：

```bash
cp /var/www/bian/data/payment/wechat-platform-certs.json /tmp/wechat-platform-certs.json.backup
```

2. 不要为了测试人工伪造微信签名。等下一次真实微信回调，或使用微信官方联调能力触发通知。
3. 当回调携带新的 `wechatpay-serial` 时，服务会自动调用 `/v3/certificates` 下载证书。
4. 回调成功后检查缓存文件更新时间。

## 14. 失败处理表

| 现象 | 最可能原因 | 处理方法 |
|---|---|---|
| 浏览器打开 webhook 是 404 | webhook 只支持 POST | 不处理，改用真实微信回调验收 |
| 下单返回 503 | provider 或密钥未配置 | 检查 `.env.production`，PM2 用 `--update-env` 重启 |
| `wechat_create_failed` | 商户号、AppID、证书或产品权限错误 | 查 PM2 错误码，核对绑定和证书序列号 |
| `wechat_certificate_download_failed` | 私钥签名错误、服务器无法访问微信、商户证书错误 | 检查网络和商户 API 证书，不要打印私钥 |
| `wechat_invalid_api_v3_key` | API V3 Key 不是 32 字节 | 在商户平台重设正确 V3 Key |
| `invalid_signature_headers` | 请求不是微信合法通知 | 确认请求经过 Nginx 时 `wechatpay-*` headers 未丢失 |
| `invalid_signature` | 平台证书不匹配或签名被篡改 | 检查 `wechatpay-serial` 和证书缓存，拒绝发权益 |
| `amount_mismatch` | 微信金额与本地订单金额不同 | 拒绝发权益，核查订单和商户后台 |
| H5 域名错误 | H5 产品未开通或域名配置不正确 | 商户平台只填 `bianmuyuan.cn` |
| 付款成功但权益未到账 | webhook 未到达、验签失败或数据库事务失败 | 查商户通知记录、Nginx/PM2 日志、orders/payment_events |
| 微信持续重复通知 | 回调没有返回成功格式 | 确认响应为 HTTP 200 和 `code=SUCCESS` |

## 15. 回滚方案

如果生产支付出现阻断问题：

1. 在 `.env.production` 设置：

```text
PAYMENT_PROVIDER=disabled
```

2. 重启并刷新环境：

```bash
pm2 restart bian --update-env
```

3. 验证支付入口返回 503，不再创建真实支付订单。
4. 不删除已有 `orders`、`payment_events` 或证书缓存。
5. 保留微信商户后台订单、Nginx 日志和 PM2 日志。
6. 修复并完成 Mock、E2E、真实小额支付后再恢复：

```text
PAYMENT_PROVIDER=wechat
```
