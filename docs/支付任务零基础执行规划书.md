> 唯一开发目录：`E:\彼岸-payment` ｜ 开发分支：`feat/payment` ｜ 本地端口：3003，备用 3004 ｜ 生产域名：`https://bianmuyuan.cn`

## 1. 完成定义

本任务不是“页面出现支付按钮”就算完成。必须同时满足：

1. Stripe 保持可用。
2. 微信 Native 和 H5 可真实支付。
3. 支付宝电脑网站和手机网站可真实支付。
4. 三种业务意图都能创建订单：月度会员、年度会员、数字人重做。
5. 微信和支付宝回调都经过不可绕过的验签。
6. 金额按分存储并与回调金额一致。
7. 重复回调不重复发权益。
8. 未配置的通道返回 HTTP 503。
9. Mock、Smoke、E2E、迁移、备份恢复全部通过。
10. Opus 无阻断评审，集成方合并并发布。

微信专项的每个点击和命令见：`docs/微信支付零基础执行规划书.md`。

### 3.2 检查接口职责

`types.ts` 中的 Provider 必须提供：

## 5. 统一下单 API 验收

### 5.1 支持的请求

统一入口：

```text
POST /api/payment
```

月度会员：

```json
{"provider":"wechat","kind":"premium_monthly"}
```

年度会员：

```json
{"provider":"alipay","kind":"premium_yearly"}
```

数字人重做：

```json
{"provider":"wechat","kind":"dh_redo","memorial_id":"纪念馆ID"}
```

### 5.2 必须验证的错误

| 场景 | 预期 |
|---|---|
| 未登录 | HTTP 401 `unauthorized` |
| kind 不支持 | HTTP 400 `invalid_kind` |
| 通道未配置 | HTTP 503 |
| 纪念馆不存在 | HTTP 404 |
| 不是纪念馆所有者 | HTTP 403 |
| 金额配置不是正整数 | HTTP 500 `invalid_amount` |

### 5.3 金额规则

服务器决定金额，客户端不能传金额。生产变量：

```text
PREMIUM_MONTHLY_PRICE_CENTS=990
PREMIUM_YEARLY_PRICE_CENTS=9900
DH_REDO_PRICE_CENTS=2999
```

分别代表人民币 9.90 元、99.00 元、29.99 元。

## 7. 支付宝零基础执行步骤

### 7.1 创建和签约应用

1. 打开支付宝开放平台：`https://open.alipay.com/`。
2. 使用企业账号登录。
3. 进入控制台，创建网页/移动网页支付使用的应用。
4. 完成应用审核。
5. 签约电脑网站支付和手机网站支付能力。
6. 记录应用 AppID。

成功标志：应用处于可用状态，并能看到电脑网站支付和手机网站支付能力。

### 7.2 生成 RSA2 密钥

1. 使用支付宝官方密钥工具生成 RSA2 密钥对。
2. 私钥只保存到密码管理器和服务器 `.env.production`。
3. 将应用公钥上传到支付宝开放平台。
4. 保存支付宝返回的“支付宝公钥”，不要误用应用公钥。

变量对应关系：

```text
ALIPAY_APP_ID=应用AppID
ALIPAY_PRIVATE_KEY=应用私钥
ALIPAY_PUBLIC_KEY=支付宝公钥
ALIPAY_NOTIFY_URL=https://bianmuyuan.cn/api/payment/webhook/alipay
```

最常见错误：把“应用公钥”填到 `ALIPAY_PUBLIC_KEY`。这里必须填支付宝公钥，因为它用于验证支付宝通知。

### 7.3 配置沙箱

如果使用支付宝沙箱：

1. 在沙箱环境创建沙箱应用。
2. 使用沙箱 AppID、沙箱密钥和沙箱买家账号。
3. 当前代码默认网关是生产 `https://openapi.alipay.com/gateway.do`；如需沙箱，先增加受控的网关配置，再使用 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`。
4. 不要用生产 AppID 请求沙箱，也不要用沙箱密钥请求生产。

未完成沙箱网关适配前，不要声称支付宝沙箱联调完成。

### 7.4 配置生产变量

在 `/var/www/bian/.env.production` 填写：

```text
ALIPAY_APP_ID=实际AppID
ALIPAY_PRIVATE_KEY=应用私钥，换行写成\n
ALIPAY_PUBLIC_KEY=支付宝公钥，换行写成\n
ALIPAY_NOTIFY_URL=https://bianmuyuan.cn/api/payment/webhook/alipay
```

然后：

```bash
chmod 600 /var/www/bian/.env.production
pm2 restart bian --update-env
```

### 7.5 电脑网站支付验收

1. 用电脑打开会员页。
2. 登录测试账号。
3. 选择支付宝和月度会员。
4. 应跳转支付宝电脑收银台。
5. 核对商户名称、订单号和金额。
6. 完成小额真实支付。
7. 查询 `orders`，确认 provider 为 `alipay`、status 为 `paid`。
8. 查询用户，确认会员为 premium。

### 7.6 手机网站支付验收

1. 用手机浏览器打开会员页。
2. 选择支付宝。
3. 应使用 `alipay.trade.wap.pay` 并跳转手机收银台。
4. 完成支付后重复数据库检查。

### 7.7 支付宝回调验收

支付宝回调地址只接受 POST 表单通知。成功处理后响应必须是纯文本：

```text
success
```

必须检查：

- RSA2 签名正确。
- `out_trade_no` 能匹配本地订单。
- `total_amount × 100` 与 `orders.amount_cents` 相等。
- `trade_status` 是 `TRADE_SUCCESS` 或 `TRADE_FINISHED` 才发权益。
- 相同 `notify_id` 不重复发权益。

伪造签名必须返回 HTTP 400。

## 8. Stripe 保持兼容

本任务不能破坏旧 Stripe 路径。必须验证：

- Stripe 未配置时返回 503。
- 月/年价格 id 缺失时返回 `price_not_configured`。
- Stripe webhook secret 缺失时不接受回调。
- `checkout.session.completed` 金额与本地订单一致后才发权益。
- 原有 `/api/stripe` 和 `/api/stripe/webhook` 在迁移期仍可工作。

真实 Stripe 联调由 Stripe Dashboard 的测试模式完成，不要使用生产卡测试。

## 9. 回调统一处理验收

统一入口：

```text
POST /api/payment/webhook/wechat
POST /api/payment/webhook/alipay
POST /api/payment/webhook/stripe
```

回调处理顺序必须是：

1. 读取原始 body。
2. Provider 验签。
3. 转换统一事件。
4. 插入 `payment_events`。
5. 查本地订单。
6. 校验金额和币种。
7. 更新订单。
8. 发放权益。
9. 提交数据库事务。
10. 返回供应商要求的成功响应。

禁止先发权益再验签或先返回成功再写数据库。
