# 彼岸 · 前端具体设计流程与设计图纸

> 依据：《前端操作界面具体设计建议》《彼岸_逝者AI_产品架构与MVP验证建议》《彼岸_线上祭品与AI生成祭品_产品判断与架构建议》三份讨论稿整合而成。
> 本文是前端实施的唯一界面要求来源：页面结构、控件清单、文案边界、状态定义、流程与埋点。

## 一、全局设计原则（所有页面强制遵守）

1. **纪念馆是主体，AI 不是主角**：用户进入的是「TA 的纪念馆」。任何入口、按钮、文案不得出现「AI 聊天」「AI 数字人」「复活逝者」等技术型/敏感命名。
2. **三个核心动作组织一切**：记住 TA（记忆）· 和 TA 说说话（想念）· 为 TA 做点什么（祭奠）。
3. **一级导航只有 3 个**：`纪念馆`｜`发现`（后续阶段）｜`我的`。AI 能力不设一级入口。
4. **商业化红线**：全部一口价明码标价；禁止虚拟币/云币/充值礼包/打榜/攀比/情感诱导话术/默认自动续费；基础祭奠（鲜花/蜡烛/清香）低门槛或免费。
5. **诚实原则**：AI 不知道就承认不知道并引导补充记忆；推测类回答必须带「基于资料的推测」标识。
6. 所有列表/对话必须定义**空状态、加载状态、错误状态**文案。
7. 「和 TA 说说话」归入**想念**；「AI 生成纪念物」归入**祭奠**。

### 1.3 视觉设计规范（庄重 · 低技术感 · 有温度）

**色彩系统**

| 角色 | 色值 | 用途与限制 |
|---|---|---|
| 主色 · 黛蓝灰 | `#3E4C59` | 导航、标题、主要文字控件；沉稳不压抑 |
| 背景 · 宣纸白 | `#F7F5F0` | 全局页面底色，略带暖度，不用纯白 |
| 辅助 · 暖灰 | `#8A8578` | 分割线、次要图标、弱信息 |
| 点缀 · 烛火橙 | `#D98E4A` | **仅**主 CTA、点灯/供奉动作、少量重点；克制使用，一屏不超过 2 处 |
| 成功 · 黛绿 | `#5B7F5C` | 保存成功、供奉完成 |
| 警示 · 赭红 | `#A85448` | 错误、删除等破坏性操作（低饱和，不用正红） |
| 文字 | 主 `#2B2B2B` / 次 `#6E6A61` / 弱 `#A39E93` | 三级文字灰度，正文对比度 ≥ 4.5:1 |

- 禁止：高饱和渐变、霓虹色、科技蓝/亮紫、纯黑纯白硬对比、玻璃拟态。

**字体与排版**

- 标题用衬线体（思源宋体），传递书卷气与纪念感；正文/UI 控件用无衬线（思源黑体或系统默认）。
- 字号阶梯（基准比常规 App 大一号，照顾中老年用户）：页面大标题 24 / 区块标题 17 / 正文 16 / 辅助说明 13。
- 行高 1.6；段落间距 ≥ 16px；每屏信息密度主动留白，不追求塞满。

**形状、质感与图标**

- 圆角统一：卡片 12px，主按钮全圆角（高度一半）；不用尖角。
- 阴影只用一级轻投影 `0 2px 8px rgba(0,0,0,0.06)`，禁止多层重阴影。
- 纪念馆皮肤允许纸纹/淡墨质感背景；禁止炫光、粒子、跑马灯特效。
- 图标：2px 线性描边、圆角端点、风格统一；祭品图标（🌸🕯🌿）保持具象温情风格，全端一致。

### 1.4 交互与动效规范

1. 动效只服务于「安静、庄重」：时长 200–300ms，ease-out；页面转场统一右进左出，弹层自底部升起，禁止弹跳/弹性过冲。
2. 点烛/献花的供奉动效 ≤ 1.2s，无金币、无连击、无排行榜；音效默认关闭，开启需在设置中明示。
3. 所有可点区域 ≥ 44×44pt；主 CTA 全宽、高 52px；相邻可点元素间距 ≥ 8px 防误触。
4. 加载超过 300ms 才显示骨架屏/加载态，避免闪烁；骨架屏用暖灰呼吸块，不用旋转菊花。
5. 对话页键盘弹出时输入框吸附键盘顶部，快捷 chip 自动收起；键盘收起后恢复。
6. 列表统一支持下拉刷新；删除类操作二次确认，确认弹窗用赭红标识破坏性。
7. 全端适配安全区（iOS 底部横条 / Android 手势区），底部固定按钮不得被遮挡。

### 1.5 适老化与无障碍

1. 支持系统字体放大至 130% 不截断、不错位、不遮挡；核心流程在最大字号下可走通。
2. 关键操作双通道反馈（颜色 + 文案/图标），不单靠颜色传达成败。
3. 所有图片有替代文本；供奉/留言等动作有明确的结果提示文案。
4. 预留「长辈模式」开关（V1.x 后置）：字号 +2、首页简化为三个大按钮（记忆/说说话/祭奠）、隐藏实验性入口。

## 二、页面设计图纸与控件清单

> 图纸为低保真线框（移动端 375px 基准）。【】= 可点击控件；（馆主）= 仅馆主/协作人可见。

### 2.0 登录注册屏（第一屏 · 登录/注册分离 2026-08-24 拍板 ✅；账号密码登录增量 2026-08-25 拍板 ✅ 当日已实施）

**页面目标**：概念落地页点「进入彼岸」后的第一站；**默认落「登录」tab**，注册需专门点击「注册」tab 进入。登录 30 秒内完成——**密码方式（账号+密码，新增默认方式，✅ 已实施）**、手机/邮箱验证码或微信扫码；注册通道**手机号 / 邮箱 / 微信三式平级**（验证码 + 密码/确认密码两行 + 昵称选填 + 协议必勾），不再「登录即注册」；注册成功后**手机号/邮箱即本产品账号**，下次直接账号+密码登录。

> **登录 tab 两种方式**：「密码」= 单账号框（手机/邮箱自动识别）+ 密码（👁）+「忘记密码？」；「验证码」= 现行「(手机|邮箱) 通道切换 + 账号 + 验证码+【获取验证码】」结构**零改动**（可继续使用验证码登录）。方式切换用与通道切换同款下划线态。
> **注册 tab 结构（增密码两行）**：手机/邮箱通道切换（与登录 tab 同构平级）→ 验证码 → **密码（👁）→ 确认密码（👁）** → 昵称（选填）→ 协议勾选（必勾）→【注册并进入】+【微信注册】；线框复用同一卡片骨架，密码两行插在验证码与昵称之间。
>
> **忘记密码浮层（卡内三步，URL 不变）**：① 输入手机号/邮箱 →【发送验证码】（60s 倒计时）→ ② 6 位验证码 + 新密码（👁）+ 确认新密码（👁）→【重置密码】→ ③ 完成态「✓ 密码已重置，请用新密码登录」+【去登录】（切回登录 tab·密码方式并回填账号）；左上「← 返回登录」。

**视觉规范（2026-08-23 拍板：光绸背景 × 暗色表单；2026-08-24 增双 tab）**

- **背景**：整屏使用概念落地页同款 WebGL 折叠光绸着色器（`src/components/concept/ConceptStage.tsx`，概念源稿 `docs/web/concept/index.html`），默认「烛夜」色板；保留右下角「换个意境」四色板切换（烛夜/黄昏/晨雾/星夜）。无 WebGL 降级为 CSS 静态径向渐变；`prefers-reduced-motion` 时光流近乎静止。背景替换原型屏 01 现行的纯暗暖渐变（`#070302` + 顶部橙色辉光）。
- **标题区**：「彼岸」衬线大字（letter-spacing .22em）+「思念有处安放」（弱字 `rgba(232,226,214,.55)`，letter-spacing .4em），与概念首页同源。
- **表单卡片**：控件结构按上方线框（tab 切换 →〔登录〕方式切换（密码/验证码）/〔注册〕通道切换（手机/邮箱）→ 账号输入 →〔密码方式〕密码行+「忘记密码？」链 /〔验证码方式〕验证码+【获取验证码】→〔注册〕密码+确认密码两行 → 昵称+协议 → 主 CTA → 微信次按钮 → 访客链）；视觉为深色半透明毛玻璃卡片——`background: rgba(16,20,28,.55)`、`backdrop-filter: blur(14px)`、1px 暖白描边 `rgba(232,226,214,.14)`、圆角 20px，保证光绸背景上文字对比度 ≥ 4.5:1。**双 tab 与方式/通道切换共用同款下划线态**（选中 `var(--ember-soft)` + 2px 下划线），tab 切换清空表单、方式切换仅清空登录 tab 输入。
- **密码行 👁 显隐**：默认密文（`type=password`），输入框尾部图标 = **划了斜线的眼睛**（当前不可见）；点击切明文，图标 = **眼睛**；纯前端态。登录一处、注册两处、忘记密码两处共五个密码行同款控件；密码行下缘弱字提示规则「8–64 位，需含大写/小写/数字/特殊符号中的至少 3 种」并实时判定。
- **主 CTA**：沿用参考图与原型 `btn-primary` 的橙色实心全宽按钮（烛火橙系渐变），与暗色烟云背景形成画面唯一强焦点，符合 §1.3「一屏不超过 2 处」的克制要求。
- **两端同源**：PC 登录页 `/[lang]/login` 已是此组合（ConceptStage + `.login-card`，双 tab 见《web/01》§9.4）；手机端原型屏 01 与两端保持一致。概念首页的「已有账号 · 登录」链接在本屏不适用（本屏默认即登录）。
- 参考图：背景意境 `docs/assets/15-login-bg-ink.png`；表单布局 `docs/assets/15-login-form.png`。

**控件与规则**

| 控件 | 规格 | 行为 |
|---|---|---|
| tab 切换（登录/注册） | 默认「登录」；「注册」需专门点击 | 切 tab 清空输入与勾选；URL 不变（纯前端态） |
| 方式切换（仅登录 tab） | 密码 / 验证码 二选一，默认「密码」 | 下划线态与通道切换同款；切换清空登录 tab 输入；「验证码」= 既有通道切换结构零改动 |
| 密码行（登录·密码方式 / 注册两行 / 忘记密码两行） | 默认密文；尾部 👁 图标（密文=划斜线眼睛，明文=眼睛） | 点击切换明/密文，纯前端态；登录仅 1 行，注册「密码+确认密码」两行（不一致即行内报错「两次输入的密码不一致」，一致前【注册并进入】置灰） |
| 密码规则（前后端同规） | 8–64 位，大写/小写/数字/特殊符号四类含 ≥3 类 | 输入行下方弱字提示 + 实时判定，不满足置灰提交；后端兜底 `weak_password` 400（不核销验证码，修正后同码重交） |
| 「忘记密码？」（仅登录·密码方式） | 右对齐文字链，紧贴密码行下缘 | → 卡内三步浮层：① 账号（手机/邮箱自动识别）+【发送验证码】（60s 倒计时）→ ② 验证码 + 新密码 + 确认新密码 →【重置密码】`POST /api/auth/reset-password` → ③ 完成态【去登录】切回登录 tab·密码方式并回填账号；成功**不自动登录** |
| 通道切换（注册 tab；登录·验证码方式） | 手机 / 邮箱 二选一，默认手机，两通道平级 | 切换即清空输入；手机号校验 `1xxxxxxxxxx`，邮箱标准格式 |
| 【获取验证码】 | 次按钮 | 点击 → `POST /api/auth/request-code`；成功后 60s 倒计时不可重发（服务端同通道 60s 限频、`too_frequent` 429）；开发环境接口回 `devCode`，原型自动回填 |
| 验证码输入 | 6 位数字，全角自动归一（服务端已做） | 错 5 次锁 15 分钟（`too_many_attempts` 429）；10 分钟过期；过期/不符统一文案「验证码错误」 |
| 昵称（仅注册 tab） | 选填，≤20 字 | 缺省提交为空，服务端建号时落「彼岸用户」 |
| 协议勾选（仅注册 tab） | 必勾复选 + 两链接 | 未勾时【注册并进入】【微信注册】置灰；后端兜底 `agreement_required` 400 |
| 【进入彼岸 / 注册并进入】 | 主 CTA 全宽 52px，文案随 tab/方式 | 登录·密码方式→ `POST /api/auth/login-password {channel,target,password}`（channel 按账号格式自动判定）；登录·验证码方式 → `verify(intent=login)`（现行不变）；注册→ `verify(intent=register, password, name?, agreed)`，成功 toast「注册成功」+ 自动登录进首页（空态再引导建馆）+ 卡下一次性弱提示「账号与密码请妥善保管」 |
| 微信扫码登录/注册 | 次按钮，文案与 `intent` 随 tab | → `POST /api/auth/wechat/qrcode {intent}` 取 `{url,state}` 跳转授权；回跳错误 `wechat_not_registered`（登录 tab 扫了未注册微信 → 引导切注册） / `wechat_already_registered`（注册 tab 扫了已注册微信 → 留登录）；注册 tab 未勾协议置灰 |

## 六、验收口径

1. 每个页面有空/加载/错误三态截图。
2. 文案边界表逐条过审（§三）。
3. 一口价弹窗元素白名单：图标+名称+价格+说明+双按钮，出现任何其他元素即打回。
4. 4 个核心页（首页/想念页/对话页/记忆档案页）先出低保真原型评审，通过后进入高保真。
5. 高保真走查对照 §1.3 视觉规范：色值、字号阶梯、圆角、阴影逐项核对，色偏/字号不一致即打回。
6. 动效走查：全部转场与反馈动效 ≤ 300ms，供奉动效 ≤ 1.2s，无音效默认关闭。
7. 适老化抽测：系统字号放大至 130% 后，首页、对话页、祭奠页核心流程可走通，无截断遮挡。
8. 可点区域抽检：所有可点元素 ≥ 44×44pt，安全区无遮挡。
