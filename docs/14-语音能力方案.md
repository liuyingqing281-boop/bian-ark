## 1. 设计原点：让「说」比「写」更容易，但不打扰

对话页是用户与逝者情感连接最深的场景（FR-02 核心）。老年用户打字不便（NFR-05 适老），语音输入把门槛降到最低；朗读则服务视力弱与「想听 TA 的声音」的情感诉求。

两条原则：

- **语音只是输入/输出方式，不改变数据模型**：🎙 说的话落库仍是文字（messages/chat_messages 不动）；🔊 朗读是文字的运行时渲染，不落库音频。
- **克制**：不自动播放、无提示音效、无语音弹幕式交互；声音出现在用户明确点击之后。

## 2. 场景规格

### 2.1 🎙 语音输入（ASR → 文字）

- 位置：对话输入框右侧 🎙 按钮（替换现有「置灰占位」，见 web/01 §4.4、前端具体设计流程 §2.4）。
- 交互：**按住说话**（或点击开始/再点结束，PC 与移动端一致），松开即上传识别；识别文字**流式填入输入框**，用户确认/修改后按既有发送链路走（moderation、500 字上限不变）。
- 录音格式：前端 AudioWorklet 采 PCM 直接编码 **WAV**（不用 MediaRecorder 的 webm——MiMo ASR 仅收 mp3/wav，避免服务端 ffmpeg 转换环节）。
- 单次上限：60 秒（对话场景足够；接近上限时 UI 轻提示，到时自动结束并提交识别）。
- 降级：MiMo 不可用或未配置 key 时，退回浏览器 Web Speech API；均不可用时 🎙 回到置灰态（文案改回「语音功能正在准备中」）。

### 2.2 🔊 朗读（TTS，文字 → 语音）

- 位置：TA 气泡左下角 🔊 小图标（11px 弱字区，不抢视觉）；用户自己的气泡不提供朗读。
- 行为：点击即流式播放（`mimo-v2.5-tts`，pcm16 流式，边收边播）；播放中图标变为 ⏸ 可中止；**不自动播放**，「纪念性 AI · 不是 TA 本人」副标题旁不做任何声音诱导。
- 音色：读取该人物角色档案中的 `voice_profile`（见 §2.3）；未配置的角色用系统默认温和音色，不引导用户去配置。
- 文本上限：单次朗读 ≤500 字（与消息上限一致），超长截断并提示。
- 降级：MiMo 不可用时退回浏览器 SpeechSynthesis（系统朗读音色），🔊 不消失。

### 2.3 角色创建「声音」步骤（音色配置）

在建馆向导（11 号方案 R2 三步流）第 2 步「TA 的故事」之后增加可选子项「TA 的声音」，也可在馆设置页事后配置。两档：

**A 档 · 选/生成一个音色（默认）**

- 预置音色列表试听选择（冰糖/白桦等，`mimo-v2.5-tts` 预置音色）；或
- 一句话描述生成：`mimo-v2.5-tts-voicedesign`，示例提示「年迈女性，语速慢，带江南口音」。生成后提供试听，确认后存档。
- 试听从固定三句文案中任选（如「慢慢来，不着急。」），不允许用户输入任意试听文案以外的内容绕过审核；试听文本同样过 `moderateText`。

**B 档 · 用 TA 生前的声音（音色复刻，本次开通）**

- 上传生前语音样本（mp3/wav，≤10MB，建议 10 秒以上清晰人声），`mimo-v2.5-tts-voiceclone` 复刻。
- **强制前置**：勾选「我是逝者近亲属或已获合法授权」声明（consent 记录入库，复用数字人 consent 约定）；不勾选不可提交。
- **人工审核**：复刻请求进审核队列（沿用 `review_status` UGC 统一约定 + admin 队列），审核通过后该角色才可用此音色；审核中状态前台明示「声音审核中」。
- **标识**：凡以复刻音色朗读的对话气泡，气泡角落标注「AI 合成声音」弱字角标（对齐备案材料 AI 生成标识制度）。
- 禁止项：名人/非本人亲属的声音复刻由人工审核把关驳回（备案材料 §4.5 既有口径）。

## 3. MiMo 平台事实清单（2026-08-23 核实）

| 能力 | 模型 ID | 调用方式 | 关键限制 |
|---|---|---|---|
| 语音识别 | `mimo-v2.5-asr` | `POST /v1/chat/completions`，`input_audio`（Base64 data URL） | 仅 mp3/wav；支持 `stream:true` 流式出字；`asr_options.language` = auto/zh/en（方言走 auto 自动识别）；计费规则已确认 |
| 语音合成 | `mimo-v2.5-tts` | 同上，`audio` 参数指定音色/格式 | 预置音色；**支持 pcm16 低延迟流式**（24kHz 单声道）；限时免费 |
| 音色设计 | `mimo-v2.5-tts-voicedesign` | 同上 | 自然语言描述生成音色；流式暂未上线（一次性返回） |
| 音色复刻 | `mimo-v2.5-tts-voiceclone` | 同上，`audio.voice` 传样本 data URL | 样本 ≤10MB mp3/wav；流式暂未上线 |

- 端点：国际 `https://api.xiaomimimo.com/v1`，国内 `https://token-plan-cn.xiaomimimo.com/v1`（上线前实测两条链路延迟后选定，见 §9）。
- 接口为 **OpenAI 兼容**，可用 OpenAI SDK 直连，换 baseURL 即可。

## 4. 技术架构

```
┌─ 浏览器 ─────────────────────────────────┐
│ 🎙 AudioWorklet 采 PCM → 编码 WAV → base64 │  useVoiceInput.ts
│ 🔊 AudioContext 流式播放 PCM16             │  useVoicePlayer.ts
└──────┬────────────────────┬───────────────┘
       │ POST /api/voice/asr │ POST /api/voice/tts
       ▼                     ▼
┌─ Vercel Serverless（Next.js Route Handler）─┐
│ lib/voice.ts（MiMo provider 封装，唯一出口）  │
│ OPENAI_API_KEY / OPENAI_BASE_URL（环境变量） │
│ → api.xiaomimimo.com /v1/chat/completions   │
└──────────────────────────────────────────────┘
```

### 4.1 环境变量（Vercel 后台配置）

| 变量 | 值 | 说明 |
|---|---|---|
| `OPENAI_API_KEY` | MiMo 平台 key | ✅ 用户已配置；**禁止 `NEXT_PUBLIC_` 前缀**（否则打进前端包等于泄露） |
| `OPENAI_BASE_URL` | `https://api.xiaomimimo.com/v1` | 代码不硬编码端点；切换国内端点只改这里 |

本地开发用 `.env.local` 放同名变量（不进 git），`npm run dev` 与线上行为一致。命名沿用 `OPENAI_*` 是因 MiMo 为 OpenAI 兼容接口，SDK 零改动；同时也让未来换 provider（讯飞/火山/Whisper）只改环境变量。

### 4.2 Vercel 侧设置

- 语音路由 `export const maxDuration = 60`（Hobby 上限内取最大，余量留给长音频 ASR；voicedesign/voiceclone 非流式调用也走此路由族）。
- `export const preferredRegion = ['hkg1']`（香港节点，离小米国内服务近；上线前与国际端点对比实测后可调）。
- 请求体上限约 4.5MB：🎙 60 秒 WAV（16kHz 16bit 约 2MB，base64 后约 2.7MB）安全；B 档 10MB 样本 base64 后约 13MB **超限**——复刻样本由 voice 路由直接收 multipart 落对象存储（Vercel 部署时若超 Serverless 上限，再升级为客户端直传 Blob）。

### 4.3 前端钩子

- `useVoiceInput`：AudioWorklet 采集 → WAV 编码 → POST `/api/voice/asr` → SSE 流式回填输入框；60s 上限与自动结束在这里实现。
- `useVoicePlayer`：POST `/api/voice/tts` → 流式收 PCM16 → AudioContext 拼接播放；⏸ 中止；降级走 SpeechSynthesis。

## 5. 合规与红线

1. **隐私政策**：语音（声纹）属生物识别信息，隐私政策需补语音数据条款——收集目的、仅传输至 MiMo API 用于本次识别/合成、不用于模型训练、样本限期删除（与备案材料 §4.3 口径一致）。
2. **备案更新**：B 档音色复刻属深度合成「语音合成」能力，备案材料需将小米 MiMo 增补为第二家第三方基础模型来源（见备案材料更新记录）。
3. **授权与审核**：B 档强制近亲属授权声明（consent 入库）+ 人工审核 +「AI 合成声音」标识，三件套与数字人视频同标准。
4. **内容安全**：ASR 回写文字、试听文案、TTS 输入文本全部过既有 `moderateText`；语音链路不成为审核旁路。
5. **产品红线**：无自动播放、无声音诱导分享、无「和 TA 语音通话」式实时全双工包装——朗读与语音输入是两个独立辅助按钮，不营造"实时通话"错觉（FR-08 庄重性 + 伦理克制）。
6. **key 安全**：任何语音接口的 MiMo key 只在服务端环境变量；前端只调 `/api/voice/*`。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| Vercel 4.5MB 请求体上限 | B 档样本走对象存储 + mediaId，不经语音接口直传 |
| 非流式接口（voicedesign/voiceclone）超时 | 走 maxDuration=60 路由；前台异步轮询结果，不阻塞创建流程 |
| 国内访问 Vercel 不稳 | 自定义备案域名；极端情况仅迁移 `/api/voice/*` 两个路由到国内云函数，前端零改动 |
| MiMo 端点选择 | 上线前实测 `api.xiaomimimo.com`（国际）与 `token-plan-cn.xiaomimimo.com`（国内）延迟，环境变量切换 |
| 免费期结束/涨价 | 服务端中转 + `OPENAI_*` 环境变量抽象，换 provider 前端零改动 |
| 老年用户方言重 | MiMo-ASR 方言（吴/粤/闽/川）能力是选型核心理由；上线前用方言样本实测一轮 |
