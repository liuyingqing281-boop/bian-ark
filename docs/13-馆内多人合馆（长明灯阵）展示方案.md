# 彼岸 · 馆内多人合馆「长明灯阵」展示方案

- 版本：v1.0（方向已经用户拍板：2026-08-23 会话确认「就这么做」）
- 日期：2026-08-23
- 上游依据：`docs/04-PRD.md` FR-02/FR-07/FR-08、`docs/四模型分工/墓园页面前端设计规格.md`（交互模型复用）、`docs/09-数据库设计.md`（表结构改动落点）
- 定位：**一个纪念馆内纪念多位逝者（1~6 人）时的排布与交互规格**。单人馆是其 N=1 特例，现有 `/hall/[id]`、`/memorial/[id]` 页面行为不变。

---

## 1. 设计原点：团聚，而非归档

多人同馆的情感本质是「他们在一起了」（夫妻合祀、父母同堂）。因此馆内多人的排布**不做卡片目录**——目录式排布把六位逝者拆成六份资料；本方案把他们放进**同一个共享场景**，访客第一眼看到的是"一家人在这里"的画面。

核心隐喻延续产品既有资产：暗色熔岩底 + 烛光金 + `/hall/[id]` 已有的「灯还亮着」🕯️ 状态。多人馆就是它的自然放大——**同一片夜空下的 N 盏灯**。

## 2. 总体结构：一个场景，三个层

```
/[lang]/hall/[馆id]
├─ 场景层（z-0/10）   长明灯阵：每位逝者 = 一盏灯，位置表达关系
├─ 抽屉层（z-30）     点灯聚焦 → 底部抽屉 = 该人物详情（生平/相册/留言/供奉）
└─ 馆级公共层         不聚焦任何灯时的默认抽屉：群像名单 + 全馆留言墙 + 合祭
```

单人馆（N=1）渲染为：场景仅一盏灯，进入页面即默认聚焦，表现与现状完全一致——**旧馆零迁移成本**。

## 3. 场景层：灯的摆位规则

### 3.1 排布原则

- **不是网格**。灯的位置表达关系：夫妻/伴侣两灯相邻，长辈灯位略高或居中，同辈大致平齐。
- 建馆时按馆主填写的代际关系自动生成初始阵（祖辈在上、父辈居中、同辈在下）；无代际信息时按入馆顺序环形散布。
- **馆主可拖拽摆位**，摆位持久化。"把爸妈的灯放在一起"这个动作本身就是祭奠行为，计入埋点（见 §8）。

### 3.2 人数边界

| 人数 | 规则 |
|---|---|
| 1 人 | 现有单人馆，行为不变 |
| 2–6 人 | 本方案适用范围；2 人（合祀）默认双灯相邻居中 |
| >6 人 | **不允许继续加人**，引导拆分至家族祠堂（FR-07 族谱树为该量级设计） |

### 3.3 状态表达

- 每盏灯独立明灭：24h 内有人祭扫则微亮（口径同现有 `candleLit`，B1 推断逻辑复用，按 `memorial_id` 分人判定）。
- 名牌随灯展示：姓名（馆主视角原文 / 访客视角按 FR-04 脱敏规则）+ 生卒年，字号克制，不喧宾夺主（视觉层级：场景 > 灯位信息 > 操作，同墓园规格 §1）。
- 不展示访问量数字、不做任何形式的热度排序（红线）。

## 4. 抽屉层：聚焦与详情（复用墓园交互模型）

与《墓园页面前端设计规格》同一套交互模型，组件直接复用：

- **聚焦**：点击一盏灯 → 镜头 400–700ms 可中断平滑聚焦（墓园规格 §4），抽屉切换为该人物详情模式。
- **详情结构**：固定身份摘要（头像/姓名/生卒/墓志铭）、独立滚动正文（生平时间轴、相册）、固定底部双主操作——「供奉」与「查看完整生平」并列，窄屏纵向堆叠、供奉在上。
- **供奉在抽屉内完成**：祭品必选、留言可选；留言/祭品默认归属当前聚焦人物，数据挂 `memorial_id`（人物级），与现有 B4/B7 写路径一致。
- **人物切换**：聚焦态下顶部出现馆内人物条（N 个小灯标横排，当前高亮），点击直接切换聚焦对象，无需退回全景。
- **抽屉三态**（收起/半展开/全展开）、手势与键盘行为、`Escape` 层级回退（供奉 → 详情 → 馆级列表 → 离开），全部沿用墓园规格 §3/§7。
- **URL 同步**：`?p=[人物id]` 记录聚焦对象；灯位坐标、镜头状态不进 URL（同墓园规格 §7 原则）。

## 5. 馆级公共层：不聚焦时的默认态

- **群像名单**：N 位逝者的小卡列表（头像 + 姓名 + 生卒 + 一行墓志铭，摘要规格同墓园卡片），点击 = 聚焦该灯。
- **全馆留言墙**：聚合馆内所有人物的留言流（`messages` 按 `hall_id` 汇总，见 §7），可按人物筛选；条目带归属标签「致 李**」（脱敏）。
- **合祭**：「为全家点灯」一个动作对全馆 N 位各产生一条供奉记录（同一 `order_id`/批次号关联）；清明集体祭拜场景一步到位。合祭动效 ≤1.2s，克制（墓园规格 §6 仪式反馈上限）。
- 馆名与馆训置于场景顶部（如「张氏家族纪念馆」），不绑定单一逝者。

## 6. 主题皮肤（两套，交互模型一致）

| 皮肤 | 场景 | 定位 |
|---|---|---|
| **长明灯阵**（默认） | 夜空/庭院，灯=星灯/莲灯 | 全用户，偏诗意 |
| **祠堂牌位墙**（备选） | 祠堂内景，正中供桌，牌位按昭穆次序（左昭右穆）排列 | 偏传统庄重，适配 P1 中老年与家族场景 |

两皮肤仅替换场景渲染与灯位视觉，聚焦/抽屉/供奉交互完全一致。灯样式（莲灯/星灯/长明灯）与皮肤可作为装饰主题 SKU，归入 FR-06 高级装饰 9.9–39.9 元档——**明码标价、无排行、无礼包**，红线不变。

## 7. 数据模型改动（落 `docs/09-数据库设计.md` B17/M8）

- 新增 `halls` 表：馆级实体（馆名、馆训、皮肤、可见性、馆主）。
- `memorials` 加列 `hall_id`：`memorials` 语义从"馆"明确为"馆内人物"，一行 = 一位逝者。
- 归属链路：`halls 1—N memorials`；`life_events / memories / messages / tributes / chat_messages / media` **仍挂 `memorial_id`（人物级）不动**，馆级聚合查询按 `memorials.hall_id` JOIN。
- 迁移：为每个存量 `memorials` 行生成一个同名 `halls` 行并回填 `hall_id`——单人馆 = 一馆一人的特例，对外 URL 与行为不变。
- 可见性三级、审核状态、脱敏规则**馆级统一**，人物继承所属馆。

## 8. 埋点与 WAR

- 新增埋点事件：`lamp_arrange`（拖拽摆位）、`lamp_focus`（聚焦某灯）、`offer_all`（合祭）。
- 摆位与合祭计入 WAR 的"祭扫动作/族谱编辑"同类行为口径（FR-12 口径变更需留版本记录）。

## 9. 验收标准

1. N=1 存量馆页面表现与迁移前逐像素一致（视觉基线比对）。
2. 2–6 人馆：任一灯可聚焦，聚焦动画 400–700ms 可中断；人物条切换 ≤1 次点击。
3. 合祭一次产生 N 条归属正确的供奉记录，留言墙按人筛选正确。
4. 拖拽摆位持久化，刷新后位置不变；摆位不计费、不限次。
5. 全馆页面无访问量数字、无热度排序；脱敏规则馆级一致生效。
6. 超过 6 人时添加入口引导至家族祠堂，不出现第 7 盏灯。
7. `prefers-reduced-motion` 下聚焦降级为瞬时切换；性能档位遵循墓园规格 §6。
