# 彼岸 · PRD 3.0 —— 产品重新定位

> 版本 v3.0 ｜ 2026-08-17 ｜ 产出方式：苏格拉底式追问（grill-me 方法论），五个决策逐层确认
> 与 2.0 的关系：2.0 是功能驱动的实现文档；3.0 是用户与价值驱动的定位校准，指导后续迭代优先级

## 0. 五个已确认的产品决策

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 核心用户 | 建馆者（馆主，逝者至亲） |
| 2 | 痛点优先级 | 人不在场（主）→ 情感无处安放（辅）→ 记忆会散、形式受限（次） |
| 3 | MVP 核心功能 | 一场能完成的线上祭奠仪式 |
| 4 | 成功定义 | 建馆 → 邀亲友入群 → 亲友完成祭奠，整条链路走通 |
| 5 | 边界 | 不做实物电商、代扫墓、族谱；保留数字人、开放元素、3D 墓园 |

## 1. 一句话定位

**彼岸：让无法到场的思念，有一场能完成的祭奠。**——面向异地至亲的线上纪念馆与家族共同祭奠平台。

## 2. 目标用户与典型场景

**主用户：馆主（建馆者）**
逝者的至亲（子女、配偶为主），30~55 岁，多数在异地工作或定居，是付费决策者与情感投入最深者。低频高情感：建馆一次，在祭日峰值与日常思念时刻反复回访。

**次用户：亲友（群组成员）**
家族中分散各地的成员。通过群组邀请进入，低频到访，完成祭奠动作后离开。

**典型场景**
1. 【峰值·获客】清明/忌日/中元节前两周，异地的馆主无法回乡，在彼岸建馆（照片、生平、墓志铭），邀请家人入群，全家族在祭日当天各自完成一场线上祭奠
2. 【日常·留存】非祭日的某个晚上，馆主想念 TA，独自打开纪念馆点一盏灯、写一句话
3. 【家族·连接】散居各地的家族成员在群组授权的纪念馆里共同缅怀，留言互动，看到彼此的祭奠痕迹

## 3. 核心痛点

- **主痛点：人不在场**——有仪式的时刻（清明、忌日）却无法到场，心意无处安放。这是有时效、有情绪峰值、会主动寻找解决方案的痛点，负责「让人来」
- **辅痛点：情感无处安放**——思念是日常的，扫墓是一年两次的；缺一个随时能「去看看」的地方。负责「让人留」
- **次级痛点：记忆会散**（老照片散落、生平无人整理）、**形式受限**（线下只能烧纸放花）——在主辅痛点被解决后自然承接

## 4. MVP 核心功能（唯一）

### 「一场能完成的线上祭奠仪式」

核心闭环：**馆主建馆 → 邀亲友入群 → 群内亲友随时随地完成祭奠动作**

- 建馆：头像、姓名生卒、墓志铭、生平、照片墙
- 邀请：群组邀请链接/邀请码，馆主控制可见范围（私有/群组/公开三级）
- 祭奠：献祭品（点烛、献花、上香、自定义/AI 生成祭品）、留言；配合火焰、光影、留言墙等仪式感反馈
- **核心闭环完全免费，不设付费墙**；付费点（AI 祭品生成、数字人、会员扩容）全部位于闭环之后

## 5. 保留能力的分层定位（决策保留项）

| 保留项 | 定位 | 边界与前置条件 |
|---|---|---|
| **AI 数字人** | 差异化卖点 + 付费增值，宣传可提及 | 置于核心闭环验证成功之后主推；上线前完成深度合成备案与「AI 生成」水印合规 |
| **开放元素** | 获客入口：公共墓园开放浏览 + 匿名献官方免费祭品 | 只开放浏览与轻互动，不做广场、信息流、私信；内容审核兜底 |
| **3D 墓园** | 视觉体验层，强化「场所感」 | 锦上添花，不承担闭环职责，不进入 MVP 验收口径 |

## 6. 成功标准（链路漏斗）

成功 = 以下链路整体走通，上线 3 个月内：

```
馆主建馆 ──(7日内发起群组邀请)──> 亲友入群 ──> 群内成员完成祭奠动作
```

| 指标 | 建议门槛 | 说明 |
|---|---|---|
| 建馆 → 7 日内完成邀请 | ≥ 70% | 馆主传播意愿 |
| 被邀者 → 入群 | ≥ 50% | 邀请触达与转化 |
| 入群成员 → 完成祭奠动作 | ≥ 60% | 仪式完成率 |
| **全链完成率** | **≥ 21%**（0.7×0.5×0.6） | 核心验收线 |
| 北极星：每周有祭奠动作的馆数 | ≥ 50 | 拉新+回访的综合体温 |
| 辅证：馆主 30 日回访率 | ≥ 25% | 验证辅痛点「随时去看看」 |

（门槛值为建议起点，首月数据回来后校准）

## 7. 明确不做的事

1. **实物祭品电商**——鲜花/祭品线下快递配送，另一门生意
2. **代客扫墓等线下服务**——O2O 重模式，与线上仪式定位冲突
3. **族谱/家族树工具**——记忆沉淀的远期延伸，不是祭奠

## 8. 与现有实现的对照（研发视角）

本 PRD 的核心闭环在当前代码库中**已全部具备**：纪念馆 CRUD 与三级可见性、群组邀请/成员管理、祭品系统（官方+上传+AI 生成）、留言与审核、公共墓园、支付与会员。**PRD 3.0 不要求新建功能，要求的是重心校准**：运营与迭代资源优先投向链路漏斗的转化率（建馆引导、邀请流程、祭奠完成率），而非继续堆功能。
