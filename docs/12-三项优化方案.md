## W1 邮箱验证码真实发送

### 现状
- 后端 `sendLoginCode`（`src/lib/notify.ts`）已集成 nodemailer：配了 `SMTP_URL` 就真实发邮件；未配时打印到日志。
- 非生产环境响应回显 `devCode`，前端自动回填——**这是开发便利，不是生产行为**。
- `@bian.dev` 测试域强制跳过 SMTP（防自动化测试连发被服务商限流）。

### 目标
用户收到真实邮件，手动输入验证码；界面不再自动回填。

### 改造点
| 层 | 改动 |
|---|---|
| 服务器配置 | `.env` 配 `SMTP_URL=smtps://user:pass@smtp.xxx.com:465` + `SMTP_FROM=彼岸 <no-reply@bianmuyuan.cn>`；阿里云/腾讯企业邮需开 SMTP 服务并生成授权码 |
| 后端 | 生产（`NODE_ENV=production`）本就不回显 devCode ✅ 无需改；补一条：生产且未配 SMTP 时 email 通道返回 503 `email_not_configured`（现在是静默 delivered:false，前端无感知） |
| 前端 | `auth.js` 的 devCode 自动回填分支保留（仅开发环境会收到 devCode）；生产环境自然不触发，无需改 |
| 短信 | 同理，`SMS_WEBHOOK_URL` 配好即真实发短信 |

### 验证口径
- 服务器配好 SMTP 后，用真实邮箱注册：收到「彼岸登录验证码」邮件 → 手动输入 → 登录成功。
- 未配置时前端 toast「邮件服务未配置，请先用手机号」。

## W2 「记忆」与「祭奠」页面重组

### 现状
- **屏04 记忆**：5 个记忆分区（TA 是怎样的人 / 我和 TA / TA 喜欢什么 / TA 怎么说话 / 基础资料），底部「添加记忆」。内容已作为想念对话的资料源（`buildChatSystemPrompt` 注入）。
- **屏05 祭奠**：供桌 + 免费三项（献花/点灯/清香）+ 付费祭品 + AI 礼物入口。
- 用户截图中的「今天想为 TA 做什么？+ 献花/点灯/清香 + 更多祭奠与礼物」区块同时出现在**首页（屏02）**——与祭奠页重复。

### 目标结构

| 页面 | 放什么 | 不放什么 |
|---|---|---|
| 首页（屏02） | 纪念馆氛围 + 想念/记忆/祭奠三个入口 | ❌ 不再内嵌「今天想为 TA 做什么」祭奠区块（去重） |
| 祭奠（屏05） | 全部祭奠动作：献花/点灯/清香/付费祭品/AI 礼物 | —— |
| 记忆（屏04） | 改为**角色信息页**：可编辑的角色资料 + 记忆分区 | ❌ 不再出现任何祭奠入口 |

### 屏04 记忆页新结构（角色信息）

```
┌──────────────────────────┐
│ TA 的角色信息             │
│ ┌──────────────────────┐ │
```

- 编辑权限：馆主/协作人（复用 `canManageMemorial`）。

## W3 「想念」对话双模式

### 两种模式定义

| | 第三方模式（现状，默认） | 模仿模式（新增） |
|---|---|---|
| AI 身份 | 纪念性助手，明确「不是 TA 本人」 | 以角色第一人称与用户对话（「我」= TA） |
| 措辞 | 涉及 TA 想法用「可能/大概」推测语气 | 用 TA 的语气、口头禅直接回应 |
| 依据 | 同样只依据记忆资料，禁止编造 | 同样只依据记忆资料；资料外的事用角色口吻承认「记不清了」 |
| 系统提示词 | `buildChatSystemPrompt` 现状 | 新增 `buildRoleplaySystemPrompt`（第一人称 + 语气模仿 + 同一套资料与红线） |

### 合规红线（模仿模式额外）
1. **进入前必经边界确认**：现有 F1 浮层文案保留给第三方模式；模仿模式用新文案——「AI 会模仿 TA 的语气和你说话。**这是 AI 的模仿，不是 TA 本人。**」点「我明白了」才进入。
2. **对话页常驻标识**：模仿模式下输入框上方常驻「AI 模仿 · 非本人」小字标签，不随滚动消失。
3. 用户问「你是真的 TA 吗」类问题时，模型须坦白 AI 身份（写进系统提示词红线）。
4. 输入输出都过 `moderateText`（现有管线不变）。
5. 呼应《备案材料-深度合成算法备案》：双模式均在生成内容侧保持可识别的 AI 合成属性。

### 前端
- 屏03 想念页顶部加模式切换（segmented 两档：「AI 助手 · 第三方」/「模仿 TA」）。
- 切到模仿模式：首次弹边界浮层（确认后本馆记住选择，不再弹）；切换即时生效，后续消息按新模式。
- 当前模式随消息发送；历史消息气泡顶部小标区分（模仿模式消息带「模仿」角标）。

### API
`POST /api/hall/chat` 请求增加可选字段：
```json
{ "memorialId": "…", "message": "…", "mode": "companion | roleplay" }
```
- 缺省 `companion`（向后兼容，旧前端不受影响）。
- 响应增加 `"mode"` 回显；`evidence` / `askMemory` / `followupQuestion` 结构不变。

### 后端逻辑
- `chat` 路由按 `mode` 选提示词构造函数；其余（权限、审核、落库、埋点）不变。
- `buildRoleplaySystemPrompt`：第一人称 + 语气/口头禅取自「TA 怎么说话」分区 + 性格取自「TA 是怎样的人」+ 同一资料集与编造禁令 + 坦白条款。
- 埋点 `hall_chat_reply` 增加 `mode` 维度（观察模仿模式使用率与留存差异）。

### 数据仓库（迁移 019）

- 历史消息默认 companion；新消息按发送时模式落库。
