## 三、数据库改动（新增 migration）

### T1. `memories` 表（G1，P0）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | uuid |
| memorial_id | TEXT | 所属纪念馆 |
| user_id | TEXT | 录入人 |
| section | TEXT | 5 分区枚举：`personality` / `relation` / `likes` / `speech` / `profile` |
| content | TEXT | ≤500 字 |
| review_status / review_reason | TEXT | 复用审核约定 |
| created_at / updated_at | TEXT | |

索引：`(memorial_id, section)`。

### T2. `messages` 表（G3，P0）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | uuid |
| memorial_id | TEXT | |
| user_id | TEXT | 作者 |
| msg_type | TEXT | `public`（留言）/ `private`（悄悄话）/ `eulogy`（悼文） |
| content | TEXT | ≤500 字 |
| review_status / review_reason | TEXT | |
| created_at | TEXT | |

可见性规则（服务端强制）：`private` 仅 `user_id` 本人可读；`eulogy` 在馆内置顶；`public` 进混合纪念流。用户名打码在前端展示层做，库内存原文。

### T3. `chat_messages` 表（G4，P1）

`id / memorial_id / user_id / role(user|ta) / content / evidence_memory_id(NULL) / created_at`。游客会话不持久化（无 user_id 时只返回不落库）。

### T4. 既有表改动

- `tributes`：不动结构；G6 混合流由查询层 union messages 实现，不加字段。
- `items`：不动；G7 复用 `price_cents` + `is_premium`。
- `memorials`：不动。

## 四、API 改动清单

### 新增

| 接口 | 方法 | 说明 | 优先级 |
|---|---|---|---|
| `/api/memories` | GET | `?memorial_id=` 按分区分组返回 + 总数；权限同 canViewMemorial | P0 |
| `/api/memories` | POST | 新增记忆（馆主/协作人，或对话闭环的「补充记忆」——后者允许普通登录用户，记 `source=chat`） | P0 |
| `/api/memories/[id]` | PATCH / DELETE | 编辑/删除（仅馆主与协作人） | P0 |
| `/api/messages` | GET | `?memorial_id=` 返回可见消息（按 G3 可见性过滤，eulogy 置顶） | P0 |
| `/api/messages` | POST | 发表留言/悄悄话/悼文（需登录；moderateText 审核） | P0 |
| `/api/hall/feed` | GET | 混合纪念流：tributes ∪ messages(public/eulogy) 按时间倒序，统一条目结构 `{kind, icon, label, sender(打码), message, created_at}` | P1 |
| `/api/me/memorials` | GET | 我的纪念聚合（创建/协作/供奉过） | P2 |

### 修改

| 接口 | 改动 | 优先级 |
|---|---|---|
| `/api/hall/chat` | ① system prompt 改从 `memories` 分区装配（无记忆时回落生平/大事记）；② 返回体增加 `evidence: { memory_id, quote, created_at } | null`：要求模型在 JSON 模式中返回引用的记忆 id，无引用则 null（前端不显示依据链接，禁止空链接）；③ 落库 `chat_messages`；④ 回答无法基于资料时返回 `askMemory: true` + 引导问题 | P0 |
| `/api/tribute` | 支持 `order_id` 关联（G7：付费祭品先下单支付，回调成功后写 tribute）；免费项维持现状 | P1 |
| `/api/items/claim` | 确认/补齐「生成物收藏到纪念馆供桌」语义（G5） | P1 |

### 不动

auth、groups、stripe webhook、digitalhumans、garden、admin、media、timeline。

## 六、阶段拆分

- **P0（最小可用闭环）**：T1+T2 迁移；`/api/memories`×4、`/api/messages`×2；`/api/hall/chat` 证据化改造；hall 页 + 想念页 + 记忆档案页接入。
- **P1**：T3 对话历史；混合流 feed；付费祭品一口价链路；礼物页三步流。
- **P2**：我的纪念聚合；发现页；旧版 memorial 页下线评估。

## 七、验收口径

1. 每个新接口冒烟脚本入 `tools/`（延续 hall-check.mjs 模式）。
2. 文案红线：接口返回与页面文案过《前端具体设计流程》§三对照表。
3. 权限：private 消息/编辑记忆 的越权访问用负例冒烟覆盖。
4. 对话：无资料问题必须返回 `askMemory: true`，禁止编造（用固定问题回归）。
5. 性能：hall 页服务端渲染首屏 < 1.5s（热缓存下）。

## 八、明确不做

- 不做虚拟币/充值/打榜/榜单任何后端字段与接口。
- 不做高拟真数字人/声音（既有 digital_humans 维持现状，不接入新界面）。
- PC 端不做独立接口层。
- 不改 `data/bian.db` 之外的任何运行数据；迁移走 `tools/db-migrate.mjs` 标准流程（可回滚）。
